# Домашнє завдання №4
Тема: Інфраструктура та мережі в DevOps

## Завдання 1. Аналіз таблиці маршрутизації

Команда: `ip route`

- Default Gateway: 172.21.32.1
- Маршрут: `default via 172.21.32.1 dev eth0`
- Інтерфейс: eth0

`default via` означає, що пакети до мереж, для яких немає окремого маршруту, надсилаються через шлюз 172.21.32.1.

## Завдання 2. Дослідження ланцюгів Firewall

Команда: `sudo iptables -L -n`

- INPUT - policy ACCEPT
- FORWARD - policy ACCEPT
- OUTPUT - policy ACCEPT

INPUT обробляє трафік, адресований самій системі, а FORWARD - трафік, що проходить через неї до інших пристроїв. У моєму виводі всі три ланцюги мають політику ACCEPT.

## Завдання 3. Мережева ізоляція в Docker

Команди:
`sudo docker run -d --name test-net nginx`
`sudo docker inspect test-net`

- Контейнер: test-net
- IP-адреса: 172.17.0.2
- Мережа Docker: bridge
- Gateway: 172.17.0.1

Контейнер має власну IP-адресу в приватній мережі Docker. Напряму з інтернету вона зазвичай недоступна, тому для доступу до сервісу ззовні потрібно опублікувати порт.

## Завдання 4. Port Mapping та NAT

Команди:
`sudo docker run -d -p 8080:80 --name web-server nginx`
`curl -i localhost:8080`
`sudo iptables -t nat -L -n`

- Результат curl: HTTP/1.1 200 OK
- Порт хоста: 8080
- Порт контейнера: 80
- IP контейнера: 172.17.0.3
- NAT-правило: `DNAT tcp dpt:8080 to:172.17.0.3:80`

Port Mapping дозволяє звертатися до Nginx у контейнері через порт 8080 хоста. Правило DNAT перенаправляє трафік із цього порту на адресу контейнера 172.17.0.3:80.

## Завдання 5. Kubernetes: Pod vs Service

1. Контейнери одного Pod можуть звертатися один до одного через localhost, бо мають спільний мережевий простір.
2. Service (ClusterIP) дає стабільну адресу для доступу до застосунку, навіть якщо IP окремих Pod змінюються. Також він розподіляє запити між Pod.
3. kube-proxy налаштовує правила переспрямування трафіку від Service до відповідних Pod.
