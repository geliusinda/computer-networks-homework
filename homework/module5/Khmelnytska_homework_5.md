# Домашнє завдання №5
Тема: Діагностика та безпека мереж

## Завдання 1. Діагностика трафіку з tcpdump

Команди:
`sudo tcpdump -i any port 80 -c 10`
`curl http://example.com`

- Перший пакет: [S] - SYN
- Другий пакет: [S.] - SYN-ACK
- Третій пакет: [.] - ACK
- TCP handshake: успішний
- Відповідь сервера: HTTP/1.1 200 OK

Усі три етапи TCP handshake відбулися. Прапорець [P.] означає PSH + ACK: пакет передає дані та підтверджує отримання попередніх.

## Завдання 2. Налаштування Reverse Proxy (Nginx)

`proxy_pass http://localhost:3000;` перенаправляє запити з `/api` на бекенд. `proxy_set_header X-Real-IP $remote_addr;` передає бекенду IP-адресу клієнта. Без цього заголовка бекенд зазвичай бачить IP проксі-сервера.

Reverse Proxy дозволяє не відкривати порт 3000 напряму в інтернет і контролювати доступ через Nginx.

## Завдання 3. Вибір алгоритму балансування

- Алгоритм: IP Hash

IP Hash зазвичай направляє запити з однієї IP-адреси на той самий сервер, тому сесія в його пам'яті зберігається. При Round Robin запити можуть потрапляти на різні сервери, де цієї сесії немає. Якщо IP користувача зміниться або сервер перестане працювати, IP Hash не гарантує збереження сесії.

## Завдання 4. Мікросегментація в Kubernetes

- Політика застосовується до Pod з міткою `app: database`.
- Вхідні з'єднання дозволені від Pod з міткою `app: backend` у тому самому namespace.
- Іншим Pod доступ за цим правилом не дозволений, якщо його не відкриває інша NetworkPolicy.

Це зменшує Blast Radius: у разі злому frontend зловмиснику складніше напряму дістатися до бази даних.

## Завдання 5. Аналіз системи виявлення вторгнень

Alert: `ET EXPLOIT POSSIBLE SQL Injection (UNION SELECT)`

IDS виявляє підозрілий трафік і повідомляє про можливу атаку. IPS у режимі блокування могла б відкинути такий пакет, якщо правило налаштоване на блокування.

Додатковий захист - WAF на рівні edge. Він перевіряє HTTP-запити та може заблокувати SQL Injection ще до того, як запит дійде до застосунку.
