Домашнє завдання №3
Тема: Веб-протоколи та прикладний рівень

Завдання 1. Аналіз HTTP-заголовків та статус-кодів

Команда: `curl -I http://example.com`

- Статус-код: 200 OK
- Location: відсутній
- Протокол: HTTP/1.1

Сервер успішно обробив запит. Перенаправлення на іншу адресу немає.

Завдання 2. Робота з методами HTTP

Команда: `curl -i -X POST https://httpbin.org/post -d "title=Test&body=Hello"`

- Статус-код: 200 OK
- Протокол: HTTP/2
- Результат: сервер отримав надіслані дані

GET використовують для отримання інформації. Його параметри часто передають в URL, а відповіді можуть кешуватися. POST передає дані в тілі запиту, наприклад для створення ресурсу, і зазвичай не кешується. Статус 201 Created означає створення ресурсу, але httpbin повернув 200 OK, бо лише прийняв і показав дані.

Завдання 3. Перевірка TLS-сертифіката

Команда: `openssl s_client -connect github.com:443 -servername github.com`

- Сайт: github.com
- Issuer: Sectigo Public Server Authentication CA DV E36 (Sectigo Limited)
- Протокол: TLSv1.3
- Cipher Suite: TLS_AES_128_GCM_SHA256
- Перевірка сертифіката: OK

Сертифікат пройшов перевірку, з'єднання захищене TLS 1.3.

Завдання 4. Аналіз безпеки Cookies

Команда: `curl -i "https://httpbin.org/cookies/set?test_session=12345"`

- Cookie ID: test_session
- Значення: 12345
- Path: /
- HttpOnly: відсутній
- Secure: відсутній
- SameSite: не вказаний

HttpOnly не дозволяє JavaScript читати Cookie та зменшує ризик викрадення його через XSS. Secure дозволяє браузеру надсилати Cookie тільки через HTTPS. У цьому прикладі обидва атрибути відсутні.

Завдання 5. Архітектурне моделювання

- Сценарій А: WebSocket. Він підтримує постійне з'єднання з браузером, тому сервер може одразу надсилати нові ціни акцій.
- Сценарій Б: gRPC. Він підходить для швидкого обміну даними між білінгом та обліком акцій, використовує HTTP/2 і Protocol Buffers.

Для оновлення графіків обрала б WebSocket, а для зв'язку між внутрішніми сервісами - gRPC.
